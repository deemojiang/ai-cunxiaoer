# 未来乡村 AI 版 · 便民服务需求清单

> 定位：以 **AI 村小二** 为核心入口的村民便民服务应用  
> 原则：**对话即服务** — 群众用说话/打字提问，AI 理解意图后提供咨询、导引、代办填报、问题上报等服务

---

## 一、产品定位

### 1.1 要解决什么问题

| 现状痛点 | AI 版解决思路 |
|---------|--------------|
| 功能多、菜单复杂，老人不会用 | 一个对话框搞定，说人话就能办 |
| 不知道找哪个模块 | AI 自动识别意图，跳转到对应服务 |
| 政策文件看不懂 | AI 用大白话解读本地政策 |
| 有问题不知道找谁、怎么描述 | AI 引导填报，自动生成结构化工单 |
| 村里服务分散在各个小程序 | 统一入口，AI 串联各便民服务 |
| 干部下班没人回应 | AI 7×24 小时先应答，复杂问题转人工 |

### 1.2 产品 Slogan

**「有问题，问村小二」** — 您的 AI 乡村生活助手

### 1.3 目标用户

| 用户 | 核心场景 |
|------|---------|
| 本村村民 | 卖农产品、找工作、问政策、报问题、参加活动 |
| 外来租客 | 了解村情、租房信息、邻里互助 |

#### 3.1.4 三种输入方式

| 方式 | 说明 | 适用人群 |
|------|------|---------|
| **打字输入** | 底部输入框输入文字，回车或点发送 | 所有用户 |
| **语音输入** | 点击麦克风说话，ASR 转文字后发送（演示模式可模拟） | 老人、不便打字的用户 |
| **附件上传** | 点击回形针上传图片，AI 识别后引导选择对应办事场景 | 报问题、报修、技能/村务等需拍照场景 |

#### 3.1.5 两种服务进入方式

| 方式 | 说明 | 适用人群 |
|------|------|---------|
| **点选服务** | 点击首页服务卡片或「更多」展开后的卡片，进入专属对话流程 | 不熟悉语音、初次使用 |
| **直接说话** | 自由描述需求，AI 意图识别后匹配场景并进入流程 | 老用户、明确需求 |

两种方式进入办事类场景后，**统一走六步办事流程**；日常问答类（天气、百科）则直接答复，不生单。

#### 3.1.6 通用问答（非办事场景）

当用户输入不属于具体办事场景时，AI 作为通用助手直接回答，不强制进入生单流程：

| 类型 | 触发示例 | AI 行为 |
|------|---------|---------|
| **今日天气** | "今天天气怎么样" | 联网查询 → 展示天气卡片（温度、风力、湿度、农事/生活建议） |
| **百科常识** | "板栗怎么保存""现在什么节气" | 联网搜索 / 知识库 → 大白话回答 + 来源标注 |
| **联网搜索** | 其他带疑问的日常问题 | 模拟/接入实时搜索 → 摘要答复 + 来源 |
| **闲聊问候** | "你好""谢谢" | 自然回应 + 引导可办事项 |

首页底部提供示例快捷提问气泡（如天气、挂号、村务公开），降低发现成本。

#### 3.1.7 顶部导航与流程指示

| 元素 | 说明 |
|------|------|
| **☰ 首页** | 返回欢迎页与服务卡片网格 |

### 3.2 统一办事流程（六步法）

所有需要处理的事项，均按以下流程执行：

```
① 识别场景  →  ② 确认事项  →  ③ 采集信息  →  ④ 确认摘要  →  ⑤ 自动生单  →  ⑥ 反馈结果
```

| 步骤 | AI 行为 | 用户操作 | 系统动作 |
|------|---------|---------|---------|
| ① 识别场景 | 根据点选或话术判断属于哪项服务 | 选择服务或描述需求 | 加载该场景的提问模板 |
| ② 确认事项 | 复述理解："您是要反映村口垃圾桶满溢，对吗？" | 确认 / 纠正 | 锁定场景类型 |
| ③ 采集信息 | 按模板逐项追问，已注册用户自动预填 | 文字 / 语音 / 拍照回答 | 结构化存储字段 |
| ④ 确认摘要 | 汇总信息供用户核对 | 确认提交 / 修改某项 | 校验必填项 |
| ⑤ 自动生单 | 生成对应类型单据并分配处理方 | — | 写入工单库、推送通知 |
| ⑥ 反馈结果 | 告知单号、预计时效、后续可查进度 | 可选评价 | 消息推送、积分记录 |

**采集原则：**
- 一次只问一个问题，避免信息轰炸
- 能从用户档案预填的不重复问（姓名、手机、所在片区）
- 支持语音回答，AI 自动转文字入库
- 非必填项可跳过，AI 标注「未提供」
- 用户可随时说「改一下地址」回到对应字段修改

### 3.3 分场景信息采集与处置方式

不同场景采集的字段不同，生成单据类型不同，后续处置路径也不同。

#### 场景 A：反映问题 / 曝光台

| 项目 | 内容 |
|------|------|
| **适用情况** | 环境卫生、道路破损、噪音扰民、违建举报、邻里纠纷等 |
| **采集字段** | 问题类型 → 发生位置 → 问题描述 → 现场照片（建议）→ 是否匿名 → 联系方式 |
| **生单类型** | 问题反馈工单 |
| **派单规则** | 环境卫生→环卫负责人；道路设施→村委基建；噪音/纠纷→网格员 |
| **处置时效** | 普通 48 小时；安全隐患 2 小时 |
| **闭环方式** | 处理完成 → 推送结果 → AI 满意度回访 |

**对话示例：**

```
用户：[点选「反映问题」]
AI：好的，我来帮您反映。请问是什么方面的问题？
    [环境卫生] [道路设施] [噪音扰民] [其他]
用户：环境卫生
AI：请描述一下具体情况，在哪里？
用户：村口公交站旁边垃圾桶满了
AI：能拍张照片吗？方便工作人员定位处理
用户：[上传照片]
AI：需要匿名反映吗？（默认显示您的姓名）
用户：不用匿名
AI：请确认以下信息：
    · 类型：环境卫生 - 垃圾桶满溢
    · 位置：村口公交站旁
    · 联系人：张大叔 138****1234
    [确认提交] [修改]
用户：[确认提交]
AI：已生成工单 #20260708001，已通知村委小张，预计 1 个工作日内处理。
    可随时问我「进度怎么样了」查询。
```

#### 场景 C：卖农产品 / 商品上架

| 项目 | 内容 |

### A.4 功能优先级建议（材料视角）

结合群众使用频率和痛点紧迫性，建议按以下顺序推进（与正文第九章 AI 版分期互补）：

#### 第一优先级（刚需高频）

1. **消息公告** — 村里通知第一时间触达
2. **云上议事厅** — 民主参与、治理透明
3. **需求帮助 / 曝光台** — 问题上报、快速响应
4. **创业政策 + 生产用工** — 就业增收
5. **村民商城 / 寨富驿点** — 农产品销售
6. **医疗健康（挂号/健康驿站）** — 看病便民
7. **老年惠餐** — 留守老人刚需

#### 第二优先级（治理增效）

8. 房屋租赁管理（有外来人口的村）
9. 积分体系 + 志愿服务
10. 三务公开 + 矛盾调解
11. 技能培训 + 星级工匠
12. 农民建房线上办

#### 第三优先级（特色亮点）

13. 驾驶舱数据展示
14. 数智旅游 / 村BA（文旅村）
15. 电商带货、研学大讲堂
16. 生态监测、古树养护
17. 关爱码、结对帮扶

### A.6 推荐落地架构

结合群众日常需要，一个较完整的未来乡村功能包建议包含：

```
【村民端小程序】
├── 首页：公告通知、快捷入口
├── 治理：议事厅、曝光台、三务公开

└── 我的：个人信息、积分、收藏、参与记录

【管理后台】
├── 内容管理：公告、活动、政策发布
├── 审核中心：议事、商品、租客、曝光事件
├── 数据管理：村民信息、房屋、资源
└── 系统管理：账号、权限、对接配置

【驾驶舱】
└── 一统三化九场景数据可视化

【线下配套】
└── 健康驿站 + 监控 + 智慧小屋（按预算选配）
```
